## 4. FAQPage: eligibility and recommendation

- **Google's current guidelines:** since August 2023, FAQ rich results appear only for well-known, authoritative government and health websites. **A commercial blockchain agency site will not get FAQ rich results**, whatever the markup says.
- **Is the markup still allowed?** Yes. FAQPage is valid schema.org markup, it is not a violation, and other search engines and AI systems can still parse it.
- **Recommendation:** keep the template's auto-generated FAQPage as long as:
  1. every question and answer in the markup appears **verbatim** in the visible FAQ section
  2. there is only **one** FAQPage block on the URL
  3. it excludes any FAQ removed during the editor-note review (e.g. the IP-ownership question)

  Do not expect a SERP enhancement from it.
- If the template generates FAQPage from the 17 FAQs in 05, no manual JSON-LD is needed. A sample of the expected output (first two entries) is below for QA:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "What is Cosmos SDK appchain development?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "It is the process of building an application-specific blockchain with the Cosmos SDK: a dedicated chain whose rules, fees, governance and validator set are designed around one product. The work covers custom Go modules, consensus configuration, token economics, IBC connections, testing, and launching and operating the network."
      }
    },
    {
      "@type": "Question",
      "name": "When should a business build its own appchain instead of deploying smart contracts?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "When the product needs control a contract can't provide. Examples include custom transaction ordering, protocol-level automation, its own fee model, permissioning, or independence from another chain's congestion and governance. If the main need is fast launch and access to an existing ecosystem's users and liquidity, smart contracts are usually the better starting point."
```
